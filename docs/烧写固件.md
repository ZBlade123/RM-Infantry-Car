# 怎么把固件烧进板子（v3.8）

每次改源码先重新编译，检查构建日志及文件时间；生成 Hex 在：

```
RM步兵战车代码\firmware\Mecanum-Car\MDK-ARM\Mecanum-Car\Mecanum-Car.hex   （约 46KB）
```

改过代码就按「方法 A」重新编译再烧；只烧现成的用「方法 B」最快。

---

## 方法 A：Keil + ST-Link（推荐，能调试）

1. 双击 `firmware\Mecanum-Car\MDK-ARM\Mecanum-Car.uvprojx`。
2. **F7** 编译，底部应显示 `0 Error(s), 0 Warning(s)`。
3. 接线（4 根，别接反）：

| ST-Link | 板子 SWD 口 |
|---|---|
| 3.3V | 3.3V（可不接，板子自己供电时只接三根也行） |
| SWDIO | DIO |
| SWCLK | CLK |
| GND | GND |

4. 右下角 **Options for Target → Debug**：选 `ST-Link Debugger` → 右边 `Settings` → Port 选 **SW**，能看到 `ARM Cortex-M3` 和 IDCODE 就通了。
5. **Flash Download** 页勾上 `Reset and Run`（烧完自动跑）。
6. **F8** 烧录。成功提示 `Programming Done. Verify OK.`

> 板子上电顺序：先插 ST-Link 再给板子上电。烧录时**电机、舵机、波箱都断开**，这是纪律。

---

## 方法 B：FlyMcu 串口 ISP（只有 USB-TTL，没 ST-Link 时）

固件是 F103，支持串口 ISP（系统 bootloader），不需要下载器。

1. 接线（USB-TTL 模块，CH340 那种）：

| USB-TTL | 板子 |
|---|---|
| TXD | **PA10**（RX） |
| RXD | **PA9**（TX） |
| GND | GND |
| 3.3V/5V | 不建议从 TTL 供电，板子单独供电 |

2. **BOOT0 拨到 1，BOOT1 保持 0**，然后给板子上电（或按复位）。这一步是让芯片进 ISP 模式，不拨就是"一直连接中"。
3. 打开 FlyMcu（`tools\` 里没有就网上搜 FlyMcu，绿色免安装）：
   - 端口：选 CH340 的 COM 号
   - 波特率：**115200**（连不上就换 9600 试）
   - 勾 **校验**、勾 **编程后执行**
   - 文件：选上面的 `Mecanum-Car.hex`
4. 点 **开始编程(P)**，进度条走完显示 `成功`。
5. **BOOT0 拨回 0**，按一下复位（或重新上电）。

> 忘了拨 BOOT0 回 0 的现象：程序不跑，串口一片安静。这是最常见的"烧完没反应"。

## 烧完之后怎么确认是新固件

蓝牙串口助手（9600 8N1，或手机 App）发：

```
p
```

应回 `PONG 1234`（数字是运行毫秒）。再发：

```
h
```

核对帮助/启动信息中的 `RM-INFANTRY-CAR 3.8` 版本；只有 `f 0/1/2/3` 不能证明版本已更新。当前固件只适配已核对的旧 F103/TB6612 板，新 Gerber 未完成引脚验证前不要烧录。

上电头 1.2 秒不会响应运动指令，这是设计好的保护，别以为坏了。

## 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| Keil 报 `No target connected` | SWD 线序/供电/芯片被读保护 | 检查 DIO/CLK 是否接反；FlyMcu 点"解除保护"再试 |
| FlyMcu 一直"连接中" | BOOT0 没拨 1 / TX-RX 没交叉 / 波特率不对 | 严格按第 2 步；TXD 必接 PA10 |
| 烧录成功但程序不跑 | BOOT0 还在 1 | 拨回 0，复位 |
| 校验失败 | hex 不是 F103C8 的 / 供电不稳 | 重新编译；换 USB 口；别用劣质杜邦线 |
| 串口没数据 | 蓝牙没连上 / 波特率不是 9600 / TX-RX 接反 | 看模块 LED：快闪=未连接，双慢闪=已连接 |
| 一发 `v` 车就复位 | 电源被电机拉垮 | 见 `docs/发射机构.md` 第 5 节 |

## 改参数后别忘了

1. 改 `Core/Inc/rm_config.h`（比如 `RM_FIRE_SHOT_MS`）。
2. **F7 重新编译**（改了 .h 一定重新编译，Keil 有时不会自动重编所有依赖）。
3. 重新烧录。
4. 发 `cal` 抄回标定值 —— 标定值在 RAM 里，断电就丢，必须写回 `rm_config.h`。

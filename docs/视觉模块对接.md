> **v3.7：以下仅为历史协议参考，不是当前接线指南。** 当前固件禁止启用视觉，PB11 是 RR 方向 IN2，不能接模块 TX。旧版“自动迁移到 PA15/PB1”的描述已失效。接线以 [接线总表](接线总表.md) 为准；H2 是 2S 电池电压，不是 12V 输出。

# 视觉模块对接（v3.4）

> 一句话：**模块算目标，我们只管把炮口转过去。** 单线接收，不回头、不全双工。

## 1. 接线

> 整车接线的唯一标准是 [`docs/接线总表.md`](接线总表.md)（§4.5 就是这个模块）。下表是它的摘录。

| 模块引脚 | 接板子 | 说明 |
|---|---|---|
| TX | **PB11**（USART3_RX） | 必接，只这一根信号线；PB11 是 FT 脚，5V TTL 可直接接，求稳串 1k |
| RX | 不接（或接 PB10，本版固件不发） | 我们不发数据，省掉半双工的坑 |
| GND | 板子 GND | **必须共地**，否则收到的是乱码 |
| 5V / VCC | 按模块手册选电源 | H2 只有 2S 电池电压，不能当 12V 电源 |

历史方案需要另行迁移 RR 方向脚；**当前固件没有自动迁移到 PA15/PB1 的实现**，也不允许启用视觉，
代价是 PA15 要关 JTAG（代码里已调用 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`，SWD 调试不受影响）。

⚠️ **视觉和总线云台（`RM_GIMBAL_MODE=2`）都占 USART3**，只能开一个，代码里有 `#error` 拦着。

## 2. 协议（默认文本行，115200 8N1，`\r\n` 结尾）

| 帧 | 含义 | 例子 |
|---|---|---|
| `a <dx> <dy>` | 目标相对**画面中心**的像素偏差，右正、下正 | `a 42 -13` |
| `<dx> <dy>` | 同上，省略 `a` 前缀（v3.4 兼容，很多 K210 例程这么发） | `42 -13` / `-25,60` |
| `t <yaw10> <pitch10>` | 目标**绝对角**，单位 0.1° | `t 1500 900` |
| `x` 或 `n` | 目标丢失 | `x` |

模块发什么就记什么，我们**不做校验和**（视觉数据脏一帧无所谓，下一帧就纠回来；
但会把认不出来的行整行丢掉，不会让脏数据甩炮口）。

## 3. 两套输入的区别（选一个用）

### 3.1 相对偏差 `a dx dy`（大多数模块都这么给）

云台每个 10ms 做一次：

```
1) 扣死区：|dx|、|dy| ≤ RM_VISION_DEADBAND_PX(8) 当 0
2) 转角度：step = dx × RM_VISION_KP_DEG10_PER_PX(3)  → 1 像素 = 0.3°
3) 限幅：单步最多 RM_VISION_MAX_STEP_DEG10(40) = 4°
4) 累加到目标角：yaw += step，pitch -= step_y
```

好处：模块不用知道云台角度，只要目标始终在画面里就一直收敛。
目标跑到画面外（dx 很大）时靠单步限幅"扫"过去，不会瞬移。

### 3.2 绝对角 `t yaw10 pitch10`

模块自己算完角度（通常它知道云台标定值），我们直接跟。响应最快，但**模块算错就会跟着错**。

## 4. 标定（10 分钟）

| 步骤 | 操作 | 期望 | 不对怎么办 |
|---|---|---|---|
| 1 | 上电，蓝牙发 `g` | 出现 `vision valid=0 mode=0 ...` | 没有这一行 = 固件不是 v3.4 |
| 2 | 用模块上位机/串口助手看它输出什么 | 有 `a …` 或 `t …` 行 | 没有 → 模块没跑起来，先别改我们的代码 |
| 3 | 模块对着目标发帧，蓝牙发 `g` | `valid=1 mode=1 dx=… dy=…` 数字会变 | `valid=0` → 波特率不对（试 9600/115200）或 TX 没接 PB11 |
| 4 | 目标移到画面右边 | `dx` 变**正** | 变负 → 模块坐标系不同，改模块配置或把 `dx` 取反（`vision_parse_line` 一处） |
| 5 | `aim 1`，手把目标往右偏 | 云台往右追 | 追反了 → `RM_VISION_YAW_SIGN` 改成 -1 |
| 6 | 目标往上偏 | 炮口抬起 | 反了 → `RM_VISION_PITCH_SIGN` 改成 -1 |
| 7 | 目标快速晃动 | 云台跟着动但不抽 | 抖 → `RM_VISION_DEADBAND_PX` 加到 15；跟不上 → `RM_VISION_KP_DEG10_PER_PX` 加到 5 |
| 8 | 挡住镜头 | 云台**停在原地**，不甩回中位 | 甩回去了 → 检查是不是 `RM_VISION_TIMEOUT_MS` 设得太小 |

## 5. 模块协议不一样怎么办（大概率会遇到）

只改两处，别动其他地方：

1. **波特率**：`rm_config.h` → `RM_VISION_BAUD`。
2. **解析**：`rm_vision.c` → `vision_parse_line()`。里面有现成的 `parse_int()` 可以复用。

### 5.0 先看模块到底发了什么（不用示波器）

蓝牙发 `g`，第二行 `vision raw=...` 就是**模块最近一帧的原文**（非可打印字节显示为 `.`）：

| 看到 | 说明 | 下一步 |
|---|---|---|
| `vision raw=` 一直空的 | 一个字节都没收到 | 查 TX 是否接 PB11、模块是否上电、有没有共地 |
| `raw=....` 一串点 | 模块发的是**二进制帧** | 走 5.1 的二进制解析，别用文本行 |
| `raw=a 42 -13` 但 `valid=0` | 文本对，但格式不是我们认的 `a/t/x` | 按 5.1 改 `vision_parse_line` |
| `raw=a 42 -13` 且 `valid=1` | 已经通了 | 直接 `aim 1` 试追 |

### 5.1 二进制帧（例如 `A5 5A ...` 打包）怎么写

把 `vision_parse_line()` 那套换成"攒字节"：在 `Vision_FeedChar()` 里判断包头 `0xA5`、按长度收满一帧、
校验（通常是累加和或 CRC8），再把里面的 dx/dy 填进 `s_dx/s_dy`。现有主机测试的写法照样能断言这些静态量
（`vision_test.c` 里已经有 `Vision_FeedChar` 的直接调用），所以照样先跑主机测试再烧板。

常见格式对照（照抄改）：

```c
/* 例：模块发 "$Y,1500,P,900#" 这种固定包头 */
else if (kind == '$')
{
    /* 自己按位置取数字，末尾设置 s_mode / s_last_ms / s_frames++ */
}
```

改完**先跑主机测试**再烧板子：

```
gcc -std=c99 -Wall -Wextra -DRM_HOST_TEST -I Core/Inc ^
    Core/Src/rm_vision.c tests/vision_test.c -o tests/vision.exe
tests\vision.exe
```

`tests\vision_test.c` 是纯解析测试，不需要板子；改解析逻辑后照着它的写法加两条断言，
比在车上蒙着试快得多。

## 6. 自动瞄准的边界（别指望它做视觉自瞄）

- **只转云台，不动底盘**。目标跑出 Yaw 的 0~180° 范围就追不到了，要靠人开车把目标带回视野。
- **不做弹道补偿**。水弹下坠靠人抬枪，或者以后加测距再算。
- **不做发射联锁**。瞄准和开火是两条独立指令：`aim 1` 只转炮口，开火还是 `f 3`。
  想做"对准才允许开火"很简单：在 `rm_app.c` 的 `RM_CMD_FIRE` 分支里加
  `if (Vision_IsValid() == 0u) break;`。
- **帧率决定跟随手感**。模块 10fps 就会一顿一顿的，能调就调到 30fps 以上；
  固件这边 100Hz 处理，不会成为瓶颈。
